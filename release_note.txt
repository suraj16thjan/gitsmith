gitsmith v0.2.2

A fast, keyboard-driven terminal UI for GitLab and GitHub, built with ratatui.
gitsmith wraps the official glab and gh CLIs and auto-detects which to use from
your git remote — one interface for issues, MRs/PRs, pipelines, jobs, logs,
diffs, and more. It reuses your existing CLI auth, so there are no tokens to
configure.

Highlights
- 11 tabs — Issues, MRs/PRs, Pipelines, Runners, Releases, Tags, Branches,
  Commits, Todos, Milestones, Members.
- Full state, not just open — issues/MRs come back open and closed (reopen a
  closed issue); open items sort above settled ones, protected branches above
  the rest.
- Detail view (Enter) — metadata, description, and the full comment thread for
  issues/MRs.
- Side-by-side diffs — syntect syntax highlighting, line numbers, sticky file
  header, and a scroll-following file list ([ / ] to jump). v on an MR or Enter
  on a commit.
- Pipeline drill-down — pipeline -> jobs -> live-tailing ANSI log with severity
  coloring and pass-through CI colors; parent/bridge jobs drill into downstream
  pipelines.
- Create & act — new MRs/PRs and issues (n) with a type-to-filter branch
  dropdown; approve/merge/close MRs, close/reopen/comment issues, retry/cancel
  pipelines and jobs — all behind a [y/n] confirm.
- Members & roles — who has access, sorted strongest-first, including
  group-inherited access on GitLab; add a member (n) with a host-native role
  picker.
- Paged lists — 100 rows/page, fetched in the background up to 500 while you
  read.
- Works anywhere — inside a repo it reads the host from the remote; outside one
  it asks (1 GitLab / 2 GitHub) and lists your repos.

Navigation & customization
- Host switcher (S) and fuzzy repo switcher (P, prefetched at startup).
- Tab management (T) — reorder and hide tabs; r restores defaults.
- Theme picker (t) — Neon, Tokyo Night, Gruvbox, Rose Pine, Catppuccin, Nord,
  Dracula, Solarized, Everforest (live preview).
- Persisted preferences — theme and tab layout saved to
  ~/.config/gitsmith/config.json (%APPDATA%\gitsmith\config.json on Windows;
  override with GITSMITH_CONFIG).
- Command visibility (x) — every glab/gh command gitsmith runs, with success
  markers.

Multi-host / multi-config
Reads glab's config (~/.config/glab-cli/config.yml, exactly where glab keeps it)
and gh's hosts.yml directly, so every configured instance is offered instantly
and offline, looked for where each CLI keeps it ($GLAB_CONFIG_DIR /
$GH_CONFIG_DIR -> $XDG_CONFIG_HOME -> ~/.config/... -> macOS Application Support
/ Windows %APPDATA%), falling back to auth status. Only host names are read —
tokens in those files are never touched.

Fixes
- Host detection now parses glab's real 4-space-indented hosts: map (previously
  only 2-space indentation was recognized), so users with multiple GitLab
  instances see all of them in the S picker. Nested per-host settings with empty
  values are correctly excluded.
- Release workflow pins cargo publish --locked and cargo build --locked so
  releases build from the committed Cargo.lock and never rewrite it mid-publish.

Install
  cargo install gitsmith --locked

Or from source:
  git clone https://github.com/suraj16thjan/gitsmith
  cd gitsmith
  cargo install --path . --locked

Requirements
- Rust (stable)
- glab authenticated for GitLab, and/or gh for GitHub
